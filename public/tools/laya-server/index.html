为什么做它

推理这件事，最该待在你自己机器上

把模型判断交给云端，很多场景里代价并不只是调用费。

「原文要先发到第三方」

客服消息、工单、邮件正文——想让模型判断，原文就得先上传到别人的服务器。

「按次计费的账单，跟着量一起涨」

每一条消息都是一次云端调用；做得越多、账单越厚。

「网络一抖，判断就排队」

每次判断都要一个网络往返；断网、内网、飞机上，直接不可用。

laya-server 把这件事搬回本机：接口形状照旧、答案格式照旧，数据、延迟和账单都留在你自己的 Mac 里。

核心能力

云端接口的一切，只是换了地方跑

对客户端是同一个接口，对你是同一台 Mac。

零改动接入 Jev 客户端

按 Jev 文档写的客户端，只改 base_url 一行。响应 {model, answers, usage} 逐字段一致，model 里如实回具体权重名，还附送 X-Request-Id 和延迟头。

权重与推理全在本机

Apple Silicon 上用 MLX 跑 Laya 的类型化决策模型；默认只监听 127.0.0.1，连局域网都不出，0 次云端调用。

自带控制台，零构建

GET / 就是一页管理界面：请求统计、纯推理耗时、MLX 显存、模型装载、改配置、优雅停机——服务自己托管，没有前端构建、没有额外依赖。

macOS 双击即用，命令行也行

原生窗口（Dock、菜单栏、⌘Q 都在），系统 WebKit 渲染，不用另装浏览器。关掉窗口服务照常跑；再双击一次也不起第二个服务，直接连上正在跑的那个。

热态约 120ms

M1 / 16GB 实测：连续请求 p50 约 120ms。启动时后台把本地权重读进内存约 3.1 秒，不挡启动——窗口和服务立刻就绪，第一个请求也是快的。

拿自己的数据接着训

出厂权重本身就是一次 1.96 小时 / 单卡微调的产物。500 条标注起步、几千条像样；训完重新标定温度，confidence 才真正属于你的场景。

获取与启动

两条启动路，挑顺手的

macOS App 双击就用；命令行一条命令。同一份服务，两种打开方式。源码在 GitHub 上，先把仓库克隆下来。

macOS App · 双击就用

不想碰命令行：生成一个原生 App 放进你的应用程序目录，双击打开，服务已经在后面跑起来。

packaging/make_macos_app.sh # → ~/Applications/LayaServer.app（秒级）

要装到别人的 Mac：build_macos.sh --dmg 出 275MB 独立包，自带 Python，对方什么都不用装（对外分发需签名 + 公证）。

命令行 · 一条命令

开发机上顺手：起服务、开窗口一步到位，缺的权重也能顺便下好。

.venv/bin/laya-console --auto-load all

只要 API 不要界面：laya-server；不开原生窗口、改用浏览器：--no-native；只起服务不弹界面：--no-browser。

窗口只是界面：这是个服务端应用，不是网页应用

  • 关窗口（红点 / ⌘W） 只是把界面收起来——服务照常跑，脚本继续调 API
  • 点 Dock 图标 窗口回来
  • 菜单栏的 laya 图标 打开控制台 / 在浏览器中打开 / 停止服务并退出
  • ⌘Q 或「停止服务并退出」 才真正停服务并退出
  • 再双击一次 App 不会起第二个服务——认出现成那个，直接把窗口连上去

每条命令的完整参数、打包与签名细节都在 仓库 README 里；独立安装包会发在 Releases。

快速上手

三步，发出第一发本机请求

克隆 → 启动 → 把客户端指过来。

1

克隆、建环境

需要 Python 3.11+；想要原生窗口，多装一步 native 依赖。

git clone https://github.com/smarty-kiki/laya_server && cd laya_server python3 -m venv .venv && .venv/bin/pip install -e ".[dev]" .venv/bin/pip install -e ".[native]" # 原生窗口（可选）
2

启动，等权重就绪

双击 App，或跑一条命令。首次会下约 2.2GB 权重（控制台的「模型」区能看着它涨）；权重已在本地时约 3.1 秒读好，不挡启动。

packaging/make_macos_app.sh # 生成 App 后双击它 .venv/bin/laya-console --auto-load all # 或者命令行一条命令
3

把客户端指过来

按 Jev 写的客户端只改 base_url 一行；中文流量把 model 写成 auto 或 laya-multilingual。

client = TypeSafeClient(base_url="http://127.0.0.1:8077", api_key="whatever")
常见问题

先把边界说清楚

它和 TypeSafe 云端的 Jev 是什么关系？

接口逐字段兼容：同一个 POST /v1/systemone，同样的 {model, answers, usage} 形状。但它本机跑的是 Laya 的 MLX 移植，和云端 Jev 不是同一份权重——JSON 对得上，概率对不上。任何按 Jev 标定过的 confidence 阈值，必须拿你自己的数据重新标定；另外 usage 里 output_tokens 恒为 0（本来就是分类，不生成文本）。

中文能直接用吗？

训练主语言是英文，中日韩文准确率低（不是平滑退化，是崩）。中文流量请把 model 写成 laya-multilingual，或写 auto 让它按 state 的语言自动挑；别用 jev-latest 处理中文。

要花钱吗？

不花。Apache-2.0 开源，推理全走本机；唯一一次性的成本是首次下载约 2.2GB 的权重。

需要什么样的机器？

Apple Silicon（MLX 只有 arm64 构建）+ macOS 14+；三份权重合计约 2.2GB，M1 / 16GB 上实测常驻 MLX 显存约 2.2GB。

断网、内网、飞机上能用吗？

能：权重落在 Hugging Face 缓存目录里，有缓存就不发网络请求，没网照常工作。没有缓存又断网时会返回 503，并在报错里说明情况和镜像配置（hf_endpoint）。另外服务空闲几十秒后的第一发会慢一点（约 380–450ms），那是 macOS 在解压冷页面，不是网络。

能直接拿 confidence 做门控吗？

不能。本机权重与 Jev 不同源，confidence 处于「未标定」状态——laya-mlx 加载时自己就会打一条警告，说温度参数落在 [0.5, 5] 之外、部分桶会失真。要做门控，先用你自己的数据重新标定温度；仓库里有完整的后训练路线（建数据集 → 训练 → 标定 → 评估 → 导出）。

同事能直接用我机器上的服务吗？

可以，两步：服务监听局域网并设一个 API Key（laya-console --host 0.0.0.0 --api-key …），对方把 base_url 指到你的局域网 IP 就行，代码一行不用改。管理面仍然只接受你本机的请求，所以对方能用推理接口、改不了你的配置。

把第一发判断，留在本机

克隆下来，双击或一条命令，然后照旧用你的 Jev 客户端——只是答案，从你自己的 Mac 里算出来。
